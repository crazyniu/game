# 小鸟归巢：规则、术语与事务（唯一规则定义）

版本：规范设计1.0 · 2026-10-31 · **DESIGNED / PENDING_GRAYBOX**。规则可评审，不代表代码已支持。规范用语与优先级见[文档入口](../README.md)。

本文拥有搬移、孵化、临时枝、完成、睡眠、目标、箱、事务与胜负定义。其他文档只引用，不覆盖。`MUST`为强制，`SHOULD`为有充分理由才可偏离的建议；未带关键词的确定性规则同样按MUST执行。

## 1. 基础规则合同

### 1.1 棋盘与移动

同一关所有初始内容与规则参数固定，重开/重玩/重进不抽新盘、不换seed；多样性在跨关设计中产生。每种总共六只，计入可见鸟、蛋、箱下token及篮中鸟；K=3–8，稳定species ID。普通枝容量6，普通短枝容量4/5，篮容量1；短枝装满4/5只同种不完成、不睡眠、不加计数。所有枝、篮、蛋使用稳定ID，右列镜像显示但不反转规则数组。

**自动事件顺序唯一约定**：枝处理顺序为固定`shelves`数组下标`0..P-1`；S1对应下标0，S2对应1，S10对应9。MUST保留该顺序，不按字符串词典序排S1/S10/S2，也不因退役重排。自动归巢、同轮多箱揭示/孵化检查、末尾多枝退役均用此顺序；每次目标刷新后重新从下标0扫描。目标接收队列另按`targets`原数组顺序取未收集前二，不能用枝顺序代替目标顺序。

数组顺序外墙→中央通道，末项外露。来源run从末项向内数**已孵化且同种**的连续鸟，只比较species/form、不比较token ID，遇异种或蛋就停。不能跨异种、跨蛋抓同种。普通移动只改变来源外露段和目标外露端。

合法来源非空、未睡眠、未盖箱、未退役；合法目标不同、未睡眠/盖箱/退役、有空位，且为空或外露为已孵化同种鸟。实际移动量`min(run,目标空位)`，一次成功来源→目标记一步，与鸟数无关。篮收一只；部分移动是本项目明确规则，不声称已验证为所有竞品通用边界。

逻辑搬移顺序MUST为：提取来源末尾Count个token的原顺序片段→从来源删除该片段→按原相对顺序append至目标末尾；不能为“外露鸟先飞”倒置逻辑数组。例来源`[B:id0,A:id1,A:id2]`，目标`[A:id3,A:id4,A:id5]`，Count=2后来源`[B:id0]`、目标`[A:id3,A:id4,A:id5,A:id1,A:id2]`。动画可先画id2起飞，但终态/回放/状态键必须仍是该顺序，不重生ID、不按ID排序。

例：来源`[A,B,B]`到已有`[B,B,B,B]`的普通五座枝，只搬1只B；来源剩`[A,B]`，目标为B5。两处合计仍B6；五座枝装满不完成、不睡眠、不归巢，剩余B需以后接回六座枝。`[A,B,A]`只选末只A。点来源抬群，再点目标；点同一来源/空白取消；非法点击取消选择并短反馈，不记步、不变状态。

### 1.2 目标、睡眠与自动归巢

目标队列每种恰一次；激活集合为原队列中未收集前两个。`[A,B,C,D]`先收B后，激活变`[A,C]`，A不丢失，不要求先左后右。

六座枝上六只**全部已孵化且同种**是完整群。种类激活→逐只归巢并清枝；非激活→睡眠冻结占位，不能拆/加。目标刷新后按§1.1固定shelves下标从0找第一个可自动归巢睡眠群，收集→刷新→再从下标0找，直到没有符合者。连锁不需玩家逐次确认。

首次满组`CompletedCount+1`，直接归巢/睡眠都计；睡眠以后归巢不再加。最多K次。计数箱`RevealAfter=n`用累计阈值，不是从现在再来n次；种类箱`RevealSpecies=s`在s首次满组时满足，含睡眠，不要求先归巢。每箱恰一种条件；开箱显露原有token，不凭空加鸟。初始禁止可见完整同种六只枝，正常内容也禁止箱下已有完整群作为免费完成捷径。


## 2. 新机制一：固定物种鸟蛋

### 2.1 规则与信息

蛋是一个预先存在的鸟token，占一个座位，有关卡确定的species和稳定egg ID；孵化只将`Egg→Bird`，不生成额外鸟、不改变总数、不抽随机种。首版蛋壳带清晰物种纹样/轮廓，玩家可预知孵化种类；它仍是被前方鸟挡住的蛋，不能搬蛋、把蛋当同色端或用它凑完整群。真正问号隐藏身份仅为后续候选，不进入这40关。篮子首版不放蛋。

当蛋前方所有token都已移开、该蛋成为逻辑最外露端且枝未盖箱，自动孵化一次。相邻多个蛋只孵最外露一个；它孵化后的鸟仍挡着后一个，必须再搬走才能揭下一只。被箱盖住时不孵；揭箱后再按同一规则检查。没有点击破蛋、计时等候、喂食付费或随机变种。

MUST拒绝正式开局可见露端未孵蛋；箱下露端蛋不算可见。受控恢复/边界夹具若出现外露蛋，先按确定规则规范化，再开放操作；正式稳定快照不应残留该状态。孵化不记玩家步数、不加完成计数；若新状态构成完整可见群，按基础完成规则只结算一次。

### 2.2 选择、代价与回退

先释放哪颗蛋决定哪种鸟先成为可移动来源，但要先为挡头run找落点；先合现有群可腾长枝，却可能把释放蛋所需缓冲用掉。物种可预知，核心是释放顺序而非猜种。难关允许多种顺序，但不能用随机孵化或无法撤回的失败惩罚制造难度。

Undo还原本次移动和孵化状态，蛋物种固定不重抽；Restart回同一布局。无需新增知识图鉴或偷窥消耗，孵化前后的同种图标保持一致。锁定一次移动的run和数量后，刚露端孵出的同种鸟也不能追加入本次飞行，需下次操作。

全知求解器有解仍不等于交互公平：必须能读懂蛋纹样、前后阻挡和释放后的合法去处。蛋与临时枝组合不能隐藏退役规则、强迫盲猜后失去唯一中转。未来若做问号隐藏身份，需要单独验证可见信息策略和免费恢复，不能沿用本版证明。


## 3. 新机制二：临时栖枝

首版临时枝仅容量4/5、开局为空，不与箱盖重叠，不是篮子，不足六座所以不会承载满组六只或睡眠群。视觉为可收拢嫩枝/临时木托，提前有“腾空后收起”图示；无鸟受伤、坠落或时间倒计时。

| 生命周期 | 触发 | 规则 |
| --- | --- | --- |
| `Unused` | 开局空、从未成功接鸟 | 保留；空着不自动消失；非法点按不启用 |
| `Armed` | 第一次成功接至少一只鸟 | 普通容量/同种端规则；仍有鸟时可反复接收和转出，不是只能搬入一次 |
| `Retired` | Armed之后第一次从非空变完全空 | 安全完成搬移后收起，不再接/出鸟；固定ID与空位置痕迹保留，不重排布局 |

留最后一只可保住该枝、以后再接**同种**；代价是占一座且不能改接其他种。把最后一只送走可能更快合群归巢、释放普通长枝，值得永久放弃临时位。不能把“永远留一只”或“永远不用临时枝”变成所有关唯一正确策略，三种决策都需有验证案例。

最后一只移动必须先有合法安全目标，不允许先收枝再处理鸟。鸟落稳再播放收枝；归巢/开箱没有特殊权限复活退役枝。首版禁止箱和临时枝同位置，因此无需处理开箱生成已退役枝。Undo从Retired完整恢复到Armed及鸟序；Undo首次接收恢复Unused空枝，**不能因为回到空就误退役**。Restart重置初始Unused。

正常主线无临时枝归巢收起情形，因为容量最多5；若未来开放临时六座枝，睡眠/自动归巢与退役顺序必须另评审，不让未支持扩展混入首版。


## 4. 一次动作的确定结算与状态机

1. 校验并锁定run/Count，按§1.1顺序搬移；首次进入临时枝使其Armed。
2. 检查受影响位置的可见外露蛋并孵化，本次run/Count不扩张。
3. 按固定shelves数组顺序检查受影响的可见完整群，首次完成计数，按当时激活集合立即归巢或睡眠。
4. **自动归巢阶段**：从shelves下标0找第一个匹配激活目标的睡眠群，归巢/刷新目标，再从0找；直到没有可归巢睡眠群。
5. **揭箱批次阶段**：用此刻完成状态一次性确定所有满足条件的箱索引，按升序先揭示本批全部箱（置null/记录事件），然后才按这些固定索引逐枝处理露端蛋孵化和完整群。逐枝Complete可立即归当前巢/刷新目标；外部睡眠群自动归巢与本批新满足的其他箱均等本批处理完，再回步骤4。无本批可揭箱时才结束循环。不得“揭一个箱→递归跑完整连锁→再揭另一个箱”。
6. 循环稳定后按固定shelves数组顺序将Armed且空的临时枝置Retired，得出逻辑胜负与事件列表。此后按[DATA_SAVE](DATA_SAVE.md)先原子提交完整逻辑终态，再演出；事件播放/视图同步结束才开放输入或展示胜利。写档失败必须进入INTERACTION定义的SaveError而非永久停Resolving。

Core先原子计算终态与有序事件，View按操作前视图演出，不能用动画回调第二次改规则。临时枝退役在稳定化末尾记录，视觉需等最后鸟安全落地；蛋孵化必须在其前方鸟离开后，不能提前泄露或穿过箱体。孵化前后物种纹样一致，不能借动画变种。

前端状态与输入锁唯一规范见[交互与动画](INTERACTION_ANIMATION.md)。睡眠、盖箱、退役是位置状态，不是全局暂停。

未胜且无合法移动才无步可走；仍可循环搬但已无解不等于“无步可走”，求解预算不足不是无解。所有目标收集且所有位置（含蛋/篮/箱）无token才胜利，最后动画结束才庆祝。退役空枝不计剩余目标。


## 5. 动作前置、后置与反例

| 动作/事件 | 前置条件 | 后置条件 | 非法/反例与回退 |
| --- | --- | --- | --- |
| Select | Idle、位置可取、外露已孵化鸟 | 仅表现选中run，规则状态不变 | 选蛋/睡眠/箱/退役枝拒绝；不记步 |
| Transfer | From/To有效且本次快照合法，目标满足§1；UI从Selected发起，纯Core/求解器不依赖选中态 | 固定数量鸟从源到目标，随后整套稳定化 | 容量不足可部分搬；异种/无空位/无效ID整次拒绝，状态键不变 |
| Hatch | 未盖箱的最外露token为Egg | 同一token同species变Bird，产生事件 | 不对内层蛋递归全孵；不加入已锁定run |
| Complete | 六座枝可见Bird六只同种，尚未完成该种 | 计数一次，归巢或睡眠 | 四/五座满、含Egg都不完成 |
| AutoHome | 睡眠群现在属于激活目标 | 清该群并更新目标，不重计完成 | 仅目标补位未匹配的群不收，不能跳目标 |
| Retire | 稳定化末尾临时枝Armed且空 | Retired，固定ID不可用 | Unused空不退；普通空枝不退；Undo还原空不触发正常结算 |
| Undo | 稳定态有前一成功Transfer | 整个事务前快照，含蛋/临时枝/箱/目标/完成 | 没历史不受理；不只倒飞一只或只恢复最后事件 |
| Restart | 稳定态/允许的流程动作 | 关卡初态、清移动历史，保留历史成绩 | 不重抽蛋；不继承Armed/Retired |

Undo不运行正向稳定化，而是直接恢复已合法稳定快照；否则Unused空枝可能被误收、蛋提前孵化。来源run/Count必须在首次状态变更前锁定，任一前置失败整个动作无副作用。

## 6. 规则不变量

- 全局每种恰六token，归巢计入已收集六只；蛋只是form，不额外生成鸟。所有稳定token ID唯一。
- `CompletedCount`等于已首次完整的物种数，睡眠后归巢不重复计数；`CollectedTargets`不重复且是目标子集。
- `Asleep`枝必须六个可见同种Bird且非激活；目标刷新后稳定态不残留可自动收集睡眠群。
- 临时枝容量4/5，Unused空、Retired空；Armed稳定态非空，临时枝上不出现Egg/Crate；篮只含已孵化Bird。
- 每步只搬同一种且Count>0，若非法则所有规则字段和历史不变；视觉/声音/随机种子不能改变合法性。
- 逻辑稳定终态按DATA_SAVE提交；视图稳定后才解锁输入。归巢动画顺序与Core事件一致，不能提前让新目标接收旧群。

字段与序列化唯一映射见[数据/存档](DATA_SAVE.md)，验证与证据状态见[验收](VALIDATION.md)。
