# 小鸟归巢（Perch Sort）产品需求文档

版本：PRD 3.0设计评审稿 · 2026-10-31 · **未实施新版规则与关卡，未完成新版可玩性验证**。

## 1. 产品目标与本次范围

这是一款离线单人 **Sorting Puzzle / Sort Puzzle（分类排序益智）** 游戏。水排序（Water Sort）是在瓶间倒同色液体；球、鸟、螺母排序采用相近的有限空间整理逻辑。本项目以小鸟归巢为主题，保留易理解的点选搬移和整群飞回家，把不同关卡的判断扩展为：腾位、周转、探蛋、救援开路、保留临时空间、预排归巢连锁。

用户要求熟悉同类游戏后融合创新，不是一比一复刻，也不是把多种小游戏拼成合集。研究取舍见[同类研究](SORTING_RESEARCH.md)。所有关卡共享同一套搬移和归巢规则，新机制服务于小鸟与栖枝世界。

本轮只交付PRD、40关设计目录、研究结论、README和协作入口，不改代码、运行关卡、美术、音频，不重画已验收UI，不启动T12扩量。首版规模40关，前五关和课程可以重新设计；所有新内容需评审与后续验证后才能替换现行数据。

| 范围 | 首版目标 |
| --- | --- |
| 统一核心 | 外露同种连续段搬移；满组六只；双激活巢；后续鸟群睡眠等待；目标补位自动连锁归巢 |
| 现有基础 | 容量4/5短枝、容量6普通枝、0–2个单座篮、计数箱/种类箱；这些已存在，不能包装成新发明 |
| 新增重点一 | **固定物种鸟蛋**：移开前方鸟后，露端鸟蛋自动孵化，种类由关卡数据预定，不随机、不增加鸟总数 |
| 新增重点二 | **临时栖枝**：开局空、容量4/5；首次接鸟后启用，之后第一次完全腾空就收起；仍有鸟时允许多次进出 |
| 容错与节奏 | 无限撤销/重开，无倒计时/强制步数失败；每关最多两类特殊机制，每五关至少一关舒缓/表现关 |
| 不进入首版 | 广告、内购、鱼币、体力、随机洗牌、竞速、交换/扩容道具、联网账号、新分析SDK；主动放飞+风闸仅保留后续实验 |

普通通关不得依赖提示、广告或额外资源。可玩性是需用实际关卡和玩家行为证明的目标，不凭一份PRD承诺已经达成。

## 3. 一局的玩法与选择

读当前两个接收巢与后续顺序，观察外露鸟群和可用位→点来源连续段→点合法目标→鸟逐只飞过去→落稳后孵化/满组/归巢/揭示按因果结算→利用新信息和空间继续整理→所有鸟回家。

六类关卡保持基础交互一致，但分别改变决策：

| 关卡身份 | 玩家本次主要判断 | 例子 |
| --- | --- | --- |
| 经典腾位 | 哪个当前群先清掉能释放完整长枝 | 先合当前第二巢，不死守左巢 |
| 长短枝/篮周转 | 哪段放短枝、何时把篮中一只还回 | 留六座枝归巢，四座枝只接力 |
| 探蛋揭示 | 先释放哪一排、给将孵化鸟留什么接收空间 | 不急着把唯一空长枝占满，先看蛋 |
| 条件救援 | 哪个完成事件能打开需要的新区域 | 等待群满组也能开种类箱，不必归巢 |
| 临时枝规划 | 何时借、留最后一只、何时放弃该缓冲 | 腾空会永久收起，但留一只也占位且只能再接同种 |
| 目标与连锁 | 提前排谁、睡眠会不会堵住下一群 | 两组排好后完成当前群，逐群自动回家 |

新增蛋改变**可操作鸟出现顺序**，临时枝改变**空间生命周期**。它们与现有周转、救援和目标顺序组合，但不要求每关同时出现；首次教学只引一个新机制。

## 4. 基础规则合同

### 4.1 棋盘与移动

每种总共六只，计入可见鸟、蛋、箱下token及篮中鸟；K=3–8，稳定species ID。普通枝容量6，普通短枝容量4/5，篮容量1；短枝装满4/5只同种不完成、不睡眠、不加计数。所有枝、篮、蛋使用稳定ID，右列镜像显示但不反转规则数组。

数组顺序外墙→中央通道，末项外露。来源run从末项向内数**已孵化且同种**的连续鸟，遇异种或蛋就停。不能跨异种、跨蛋抓同种。普通移动只改变来源外露段和目标外露端。

合法来源非空、未睡眠、未盖箱、未退役；合法目标不同、未睡眠/盖箱/退役、有空位，且为空或外露为已孵化同种鸟。实际移动量`min(run,目标空位)`，一次成功来源→目标记一步，与鸟数无关。篮收一只；部分移动是本项目明确规则，不声称已验证为所有竞品通用边界。

例：`[A,B,B,B]`到`[B,B,B,B,B]`六座枝只搬1只B，来源剩2只B；目标B6按当前巢归巢或睡眠。`[A,B,A]`只选末只A。点来源抬群，再点目标；点同一来源/空白取消；非法点击取消选择并短反馈，不记步、不变状态。

### 4.2 目标、睡眠与自动归巢

目标队列每种恰一次；激活集合为原队列中未收集前两个。`[A,B,C,D]`先收B后，激活变`[A,C]`，A不丢失，不要求先左后右。

六座枝上六只**全部已孵化且同种**是完整群。种类激活→逐只归巢并清枝；非激活→睡眠冻结占位，不能拆/加。目标刷新后从枝ID0找第一个可自动归巢睡眠群，收集→刷新→再从0找，直到没有符合者。连锁不需玩家逐次确认。

首次满组`CompletedCount+1`，直接归巢/睡眠都计；睡眠以后归巢不再加。最多K次。计数箱`RevealAfter=n`用累计阈值，不是从现在再来n次；种类箱`RevealSpecies=s`在s首次满组时满足，含睡眠，不要求先归巢。每箱恰一种条件；开箱显露原有token，不凭空加鸟。初始禁止可见完整同种六只枝，正常内容也禁止箱下已有完整群作为免费完成捷径。

## 5. 新机制一：固定物种鸟蛋

### 5.1 规则与信息

蛋是一个预先存在的鸟token，占一个座位，有关卡确定的species和稳定egg ID；孵化只将`Egg→Bird`，不生成额外鸟、不改变总数、不抽随机种。首版蛋壳带清晰物种纹样/轮廓，玩家可预知孵化种类；它仍是被前方鸟挡住的蛋，不能搬蛋、把蛋当同色端或用它凑完整群。真正问号隐藏身份仅为后续候选，不进入这40关。篮子首版不放蛋。

当蛋前方所有token都已移开、该蛋成为逻辑最外露端且枝未盖箱，自动孵化一次。相邻多个蛋只孵最外露一个；它孵化后的鸟仍挡着后一个，必须再搬走才能揭下一只。被箱盖住时不孵；揭箱后再按同一规则检查。没有点击破蛋、计时等候、喂食付费或随机变种。

稳定开局原则上不放外露未孵蛋；格式读入/恢复仍需规范化外露蛋，再开放操作。孵化不记玩家步数、不加完成计数；若新状态构成完整可见群，按基础完成规则只结算一次。

### 5.2 选择、代价与回退

先释放哪颗蛋决定哪种鸟先成为可移动来源，但要先为挡头run找落点；先合现有群可腾长枝，却可能把释放蛋所需缓冲用掉。物种可预知，核心是释放顺序而非猜种。难关允许多种顺序，但不能用随机孵化或无法撤回的失败惩罚制造难度。

Undo还原本次移动和孵化状态，蛋物种固定不重抽；Restart回同一布局。无需新增知识图鉴或偷窥消耗，孵化前后的同种图标保持一致。锁定一次移动的run和数量后，刚露端孵出的同种鸟也不能追加入本次飞行，需下次操作。

全知求解器有解仍不等于交互公平：必须能读懂蛋纹样、前后阻挡和释放后的合法去处。蛋与临时枝组合不能隐藏退役规则、强迫盲猜后失去唯一中转。未来若做问号隐藏身份，需要单独验证可见信息策略和免费恢复，不能沿用本版证明。

## 6. 新机制二：临时栖枝

首版临时枝仅容量4/5、开局为空，不与箱盖重叠，不是篮子，不足六座所以不会承载满组六只或睡眠群。视觉为可收拢嫩枝/临时木托，提前有“腾空后收起”图示；无鸟受伤、坠落或时间倒计时。

| 生命周期 | 触发 | 规则 |
| --- | --- | --- |
| `Unused` | 开局空、从未成功接鸟 | 保留；空着不自动消失；非法点按不启用 |
| `Armed` | 第一次成功接至少一只鸟 | 普通容量/同种端规则；仍有鸟时可反复接收和转出，不是只能搬入一次 |
| `Retired` | Armed之后第一次从非空变完全空 | 安全完成搬移后收起，不再接/出鸟；固定ID与空位置痕迹保留，不重排布局 |

留最后一只可保住该枝、以后再接**同种**；代价是占一座且不能改接其他种。把最后一只送走可能更快合群归巢、释放普通长枝，值得永久放弃临时位。不能把“永远留一只”或“永远不用临时枝”变成所有关唯一正确策略，三种决策都需有验证案例。

最后一只移动必须先有合法安全目标，不允许先收枝再处理鸟。鸟落稳再播放收枝；归巢/开箱没有特殊权限复活退役枝。首版禁止箱和临时枝同位置，因此无需处理开箱生成已退役枝。Undo从Retired完整恢复到Armed及鸟序；Undo首次接收恢复Unused空枝，**不能因为回到空就误退役**。Restart重置初始Unused。

正常主线无临时枝归巢收起情形，因为容量最多5；若未来开放临时六座枝，睡眠/自动归巢与退役顺序必须另评审，不让未支持扩展混入首版。

## 7. 一次动作的确定结算与状态机

1. 校验并搬移可见run，记录实际Count；首次进入临时枝使其Armed。
2. 检查来源可见外露蛋并孵化，锁定的本次run和Count不扩张。
3. 检查本次受影响的可见完整群，计首次完成；按当前目标归巢或睡眠。
4. 目标刷新，按固定ID处理自动归巢链；不重复计完成。
5. 按ID揭示满足条件箱，检查新外露蛋与可见完整群，再重复完成/归巢/揭示至稳定。
6. 稳定化末尾将Armed且空的临时枝置Retired；事件全部播放完、视图与逻辑一致后判胜/无步可走，保存并开放输入。

Core先原子计算终态与有序事件，View按操作前视图演出，不能用动画回调第二次改规则。临时枝退役在稳定化末尾记录，视觉需等最后鸟安全落地；蛋孵化必须在其前方鸟离开后，不能提前泄露或穿过箱体。孵化前后物种纹样一致，不能借动画变种。

状态机：`Loading→Entering→Idle/Selected→Resolving→Presenting→Idle/Won/NoMoves`。睡眠、盖箱、退役是位置状态，不是全局暂停。动画/模态/转场期间不接受也不缓存棋盘、撤销、重开、提示、下一关；暂停请求等稳定点打开。旧动画/异步提示在切关销毁后失效。

未胜且无合法移动才无步可走；仍可循环搬但已无解不等于“无步可走”，求解预算不足不是无解。所有目标收集且所有位置（含蛋/篮/箱）无token才胜利，最后动画结束才庆祝。退役空枝不计剩余目标。

## 8. 撤销、帮助、评级与存档

Undo无限，撤回上一成功移动及全部后果：鸟序、蛋状态、临时枝Unused/Armed/Retired、完成数、箱、睡眠、目标队列与自动连锁。非法点击/选择/提示不入移动历史。Restart回初始布局，所有临时枝Unused，蛋回初始壳和原物种纹样。

现行评级为撤销+重开0次三星、1–3次两星、其余一星，提示不降星；星级不控制通关/解锁，历史最高星保留。**候选改进**：通关固定完成奖章，另设不惩罚撤销的效率奖章，鼓励探蛋和临时枝试验；待真人测试与产品评审，不混写成当前已实现或本轮必改UI。

提示现行每关终身最多3次、节点6000、界面等待1.5秒，失败/超时/未知/失效不扣；新规则需复测预算。建议分层为“说明当前约束→高亮可考虑来源→给一条已证明的首步”，同一次请求逐层展开只在有效首步展示后扣一次，避免一次全部剧透。限次是否保留待学习测试，普通通关始终无需提示。无广告/付费救援流程。

拟新rulesVersion和catalogId，保存内容hash、token/egg ID、类型/物种、临时枝状态、移动历史、稳定棋盘/校验键及旧进度/设置。快照或回放择一为状态权威，另一种作一致性校验。原子写临时文件→替换→保留上一稳定备份。

旧v2同号关不是新布局；旧From/To不能强行回放。迁移保留通关与最高星/提示记录，当前局按新catalog对应关重开并说明“关卡更新，已重新开始本关”；内容映射在catalog冻结时确认，不悄悄清空全部进度。损坏主档尝试匹配备份，均失败保留原件并安全重开；未来版本不覆盖为空档。系统杀进程恢复上次完整稳定事务，不能出现半只鸟、蛋重复孵化或枝退役但鸟还占其上。

| 21–25 | 临时空间规划 | 安全借用→留最后一只→周转→主动放弃；25舒缓 |
| 26–30 | 已教机制双组合 | 蛋/临时枝、救援/临时枝、篮/蛋；30无特殊机制放松 |
| 31–35 | 目标顺序协同 | 预排连锁与不同辅助机制；35舒缓 |
| 36–40 | 综合与完成感 | 熟练组合，38降低负荷，39挑战，40归巢表现关 |

每关最多两类特殊机制，按`短枝/篮/蛋/箱/临时枝`五个类别计；同类多个对象不算新机制但仍限制数量。普通目标队列/睡眠是基础，不算特殊。鸟种增加时降低局部剥层，不同时叠所有压力。临时枝自带容量4/5视为临时枝一类；额外普通短枝另计短枝一类。

## 10. 动画与交互合同

时长均为**本项目建议设计值**，不是竞品实测。沿用现有原创角色/菜单UI与136px鸟画布；新蛋、临时枝状态提示为后续必要资源，不在本轮生成或重画。动画期间输入锁覆盖完整事件链。

| 触发 | 逐阶段表现与可操作时机 | 建议时长 |
| --- | --- | --- |
| 入场 | 菜单Logo先退场→两列栖木进入→鸟落枝→目标清楚；全部落稳才点选 | 0.55–1.05s |
| 选中 | 仅run抬30px、白描边/少量星点，其他鸟不抬；结束可点目标/取消 | 0.12–0.18s |

## 11. 验证与验收

### 11.1 先验证三组灰盒

见[灰盒合同](LEVEL_DESIGN.md#7-先行灰盒与逐步推演)。先证明安全探蛋、临时枝重复借用/留一只、主动放弃临时枝的局面真实存在，再做1–5/11/21/22/25样板，最后扩40。灰盒是中间状态测试夹具，允许Armed非空，不等于正式关开局。

### 11.2 每关入库闸门

1. **结构**：每种六token含蛋/篮/箱；容量/目标/ID合法；临时枝开局空、容量4/5、无箱重叠；退役枝无token；蛋物种固定，数据不丢失。
2. **Core最优与回放**：新Solver区分蛋/鸟、临时生命周期、完成/箱/睡眠状态，键含rules/content身份；获得`Solvable && Optimal && Bound=Exact`并逐步回放到全归巢。预算耗尽=未知，拒绝或待调，不填假最优值。
3. **公平探索**：全知解只是下限证据；再给仅依据当时可见信息的安全探路、所有揭示分支的恢复证据；重点查蛋+临时枝是否迫使盲猜。
4. **机制有效**：记录孵化顺序、临时枝首次接收/多次接收/退役、篮进出、箱条件、自动连锁。禁篮/禁短枝/禁临时枝对照，只有证明无解/更长才写“必需/更优”。
5. **差异与节奏**：种类标准化、镜像、同条件位置重排做内容同构分析（不改变运行ID）；检查主决策签名，连续三关同模板必须重做。每五关有低负荷关，允许最优步数回落。
6. **实机与恢复**：真实无帮助胜利、输入锁、撤销整链、杀进程/恢复、不同屏幕/灰度/静音；JSON、求解证书、测试/录屏绑定同一hash。

蛋孵化可能零移动地合并同种块，旧“块数减一”下界不能直接沿用并宣称最优；先用0下界的正确搜索，或重新证明新下界。旧最优值和旧40关证书不为新布局背书。旧测试的minMoves/buriedBirds逐关不下降应在实施时评审更新，不能删守恒和最优证明测试。现行`List<int>`、`GetRun`、`Clone/GetStateKey`、`LevelValidator`、生成器、提示和存档均需适配，不能只加两个贴图就声称实现。

### 11.3 真人目标（待测）

至少5名新玩家先测灰盒，再测首五关和每章代表关；至少4/5在60秒内理解来源→目标、满组等待，且能在腾空前说出临时枝会收起。记录探蛋时的已知信息、首次误解、撤销点、主动退出点及“这关重复”的原话。若玩家一直回避临时枝，或永远留一只才可玩，重做布局或删机制，不增加强制使用任务掩盖问题。

期望时间仅调参：1–5约20–75秒，6–20约1–2.5分钟，21–40约2–4分钟，舒缓关回落；不用倒计时惩罚。首版不为调研新增SDK，人工记录即可。
