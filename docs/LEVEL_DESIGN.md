## 1. 读表、参数与共同闸门

A..H对应species0..7；每种总共六token，蛋和箱内鸟也计数。目标是全部回家，Q为顶部完整接收队列，前二未收集激活。S1..SP按左上、右上、下一行顺序固定编号，篮为独立固定ID；数组外墙→通道，末项外露，右列只镜像显示。

每关参数明确K/枝数P、Q及五类特殊对象：普通短枝S（容量4/5）、篮B（数量0–2）、蛋E（个数及位置约束）、箱X（枝位和完成条件）、临时枝TMP（枝位和容量）。未写的对象均为0，其余枝全六座。临时枝开局空、无遮盖无蛋，容量4/5；普通短枝不会收起。X与TMP不能同位置，篮不放蛋。每关不超过两类特殊对象；目标/睡眠为基础机制，不计特殊类。

下文“预期路线”是策划主路径，不是已求最优或唯一解。若写“更优/不可绕过”，必须补受限求解对照；未知写未知。主路径要包含该关特定事件，不以“有一个蛋/篮/箱”代替机制实际发生。所有正式关开局禁止可见完整群，灰盒中间状态除外。

蛋首版带物种纹样，玩家可预知种类；`E(C)`表示固定C种蛋，未露端不能移动、不能加入run。问号盲猜不进入这40关。临时枝只在首次接鸟之后再腾空才收起，不用的空枝不消失。参数区TMP只代表临时枝，物种F仍是鸟种；参数B1/B2代表篮数量，普通叙述A1/B2等为鸟种数量。K和最优步数不要求每关非递减，舒缓关可以降低规模。

所有关卡鸟种、数量、位置顺序、枝容量/位置、Q、蛋物种、箱条件和临时枝都MUST冻结为固定资源；Restart/Replay/重进同一hash恢复同一初态，禁止运行时AI随机补数组。未完整列数组的卡必须标未冻结，不以合同替代固定内容。

每张卡共同验收：结构守恒→新Core最优求解及逐步回放→主决策事件→错误操作Undo恢复→无帮助实机路径→可读性与内容hash绑定。**本轮项目Core proofStatus/playtestStatus仍未运行；独立文档模拟状态单独记录，不与运行证明混用**；§7和固定附录仅提供文档推演，不能当运行证书。

## 7. 先行灰盒与逐步推演

以下三个夹具验证机制边界和关键选择，**不是正式关开局**；G2/G3有已启用临时枝，因此允许初始Armed非空。以下只是文档演算，本轮未运行新Core，也未证明最优。目标均A/B/C，所有鸟种计数各六；S1..按表逻辑ID，不把显示镜像当数组反序。

### G1：释放蛋后，下一次才能搬新鸟

全六座，无遮盖无篮无临时枝：S1=`A3,E(C),B2`；S2=`B4,C2`；S3=`C3,A3`；S4/5空。E(C)壳标清C。

1. S1→S4搬B2，S1剩A3、E(C)，露蛋原位孵C1。此次只搬B2，C不追飞。
2. S2→S1搬C2，S1变A3C3，S2剩B4。
3. S3→S5搬A3，S3露C3。
4. S1→S3搬C3，C6睡眠，S1露A3。
5. S5→S1搬A3，A归巢，C补位后自动归巢。
6. S4→S2搬B2，B归巢，全部为空。

验收：6步设计见证合法、蛋token与种类不变、相邻蛋变式只孵外侧一个；Undo第1步恢复原壳与B2，第一次移动Count不扩张。普通初级探蛋可预测释放与安全接收。

### G2：临时枝留一只后还能再次接收

S1为临时四座且Armed，内容A3；S2普通四座A2；S3六座B3A1；S4六座C3B3；S5六座C3；S6六座空。这里额外一根普通短枝服务边界验证，不当作尚未验证正式关结构。

1. S1→S2，目标只余2，搬A2；S1留A1，仍Armed不退役，S2=A4。
2. S3→S1搬A1，S1=A2，S3露B3。证明同一临时枝不是只能接一次。
3. S4→S3搬B3，B6归巢；S4露C3。
4. S4→S5搬C3，C6归巢。
5. S2→S6搬A4（普通S2空着保留）。
6. S1→S6搬A2，A6归巢；稳定化时空S1退役，全鸟回家。

验收：保留末只的空间成本可见，不能再接异种B；二次接同种合法，末次腾空才退役。Undo第6步恢复Armed A2和S6 A4；Undo最初接收动作的另构夹具恢复Unused空枝。与“不借临时枝”的对照是否更长仍需新Core求解，本文不称必需。

### G3：主动放弃临时枝换长枝空位

S1临时四座Armed A1；S2六座A5；S3六座B3C3；S4六座C3B3；S5六座空。

1. S1→S2搬最后A1，A6立即归巢腾出六座长枝；空S1退役。
2. S3→S5搬C3，S3露B3。
3. S4→S3搬B3，B6归巢，S4露C3。
4. S4→S5搬C3，C6归巢，全空。

验收：退役不妨碍完整通关；可见“丢4座但腾6座”的收益，反驳永远留一只。Undo第1步恢复A1临时枝与A5长枝、目标/完成数，不能复活出额外鸟；鸟安全落位后才收枝。
