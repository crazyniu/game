# Perch Sort — 设计文档（工作名，Claude 维护，唯一权威）

玩法对标 Cutie Sort（有限空间内搬移角色并按种类归类），题材、美术、规则细节、命名全部原创：猫 → 小鸟，架子 → 栖木，猫窝 → 树冠。

## 核心规则 v2（2026-10-31 依据用户整理的《Cutie Sort》实机详版文档重定；取代此前自拟的 v1 规则）
v1 的问题：容量 4、单只搬运、任意同种集齐即清空、无顶部目标——与对标玩法不同。v2 向对标靠拢，**机制照搬，主题/美术/数值/文案原创**；原作未验证的细节由我们自己决定并写明。

### 棋盘
- 栖木（shelf）容量 **6**。栖木分左右两列，面向中央通道。逻辑上 `Birds[0]` 是靠外墙一端，`Birds[last]` 是**朝通道的外露端**；左列画成从左向右排，右列镜像（外露端在左）。
- 每种鸟恰好 6 只。所有鸟都在栖木、篮子或被板条箱遮住的栖木上。
- **篮子（basket）**：容量 1 的临时位，不参与目标，只能放 1 只；每关 0–2 个（教学关少，后期 2 个）。
- **板条箱（crate）**：盖住一整根栖木及其上的鸟，使其不可见、不可操作。揭示条件二选一：`RevealAfter=n`（盘面累计完成 n 次栖木后揭示，完成=集齐 6 只同种，无论归巢还是睡眠）或 `RevealSpecies=s`（种类 s 完成后揭示）。揭示后该栖木与普通栖木无异。

### 目标（顶部鸟巢）
- 每关有一个有序的目标队列 `Targets`（每种鸟出现一次）。**当前激活目标 = 队列中尚未收集的前 2 个**。
- 目标是约束，不是装饰：只有激活目标的种类才会被归巢。

### 操作与移动
- 点来源栖木 → 外露端**连续同种的一段**（run）被整体选中；再点目标 → 合法则移动，不是逐只拖拽。
- 合法条件：来源非空且非睡眠且未被遮挡；目标 ≠ 来源，非睡眠、未被遮挡、有空位，且目标为空或目标外露端鸟与来源 run 同种；篮子只能收空位。
- 实际移动数量 = min(run 长度, 目标空位数)（容量不足时部分移动；这是**我们的规则**，原作未验证）。
- 被异种隔开的同种鸟不是同一连续段。

### 集齐、睡眠与归巢
- 一次移动后，若目标栖木恰好 6 只同种：
  - 若该种是**激活目标** → **归巢**：栖木清空，该目标被收集，队列补位（新的激活目标出现）。
  - 否则 → **睡眠**：全排趴下，继续占位且**冻结**（不可作为来源或目标；这是我们的规则）。
- 目标刷新后，若有睡眠栖木的种类变成激活目标，则**自动归巢**（无需玩家操作，可连锁，按栖木编号顺序处理直到稳定）。
- 每次完成（归巢或睡眠）都会触发板条箱揭示检查。
- 状态由实际内容重新计算，不存冗余“已完成”标记（睡眠标志除外，因它是规则状态）。

### 胜负
- 全部目标收集（所有鸟已归巢）即通关。
- 死局：未通关且无合法移动 → 弹出撤销/重开。无倒计时、步数、体力、失败惩罚。
- 撤销：无限步，还原包括睡眠、归巢、目标队列、板条箱状态。重开回到初始。

### 表现要点（对标但原创）
- 选中：抬升 + 白描边 + 小星点；移动：run 内逐只错峰弧线飞行，姿态转向；落稳后逐只恢复坐姿。
- 睡眠：压低、闭眼、间歇飘 Z。归巢：逐只沿弧线飞向对应鸟巢，入口暖金闪光，对勾，目标替换（旧巢上滑退出、新巢进入），自动连锁收集。
- 板条箱揭示：箱体消失，新鸟排短暂浮空后落稳。通关：暗场庆祝 + 彩纸 + 结算页（大角色拿奖杯）。
- **不做**：广告、内购、鱼币经济、交换/扩容道具（首版）。结算页保留 Continue。

### 关卡
- 40 关，JSON。字段：id、version=2、capacity=6、baskets、shelves（含 side、birds、crate）、targets（有序队列）、solverMinMoves、difficulty、seed。
- 种类数 K：3→8（容量 6 使状态空间远大于 v1，上限以求解器能证明可解为准）；板条箱第 ~10 关起出现；篮子 0→2。
- 每关必须被求解器**证明可解**并给出最少步数（在节点预算内）；求解失败的候选不得入库。

## 技术
- Unity 6000.6.7f1，C#，2D URP 或内置 2D 渲染（以能出 Android/iOS 包为准）。
- 逻辑层 `Assets/Scripts/Core` 纯 C#，不引用 UnityEngine；独立 asmdef `PerchSort.Core`；EditMode 测试 `Assets/Tests/EditMode`。
- 表现层 `Assets/Scripts/View`、UI `Assets/Scripts/UI`，只读取 Core 的状态并播放动画；逻辑与动画分离，动画期间锁输入。
- 存档：版本化 JSON（Application.persistentDataPath），仅在稳定状态写入，覆盖前保留上一份快照。
- 竖屏，参考分辨率 1080×1920，使用 Safe Area。

## 视觉方向
- 柔和明亮的森林/花园，暖色背景，奶油色栖木。
- 10 种小鸟，**轮廓和花纹必须各不相同**（羽冠、尾羽、翅斑、体型），不能只靠颜色区分（色盲可辨）。
- 统一光源、线宽、阴影；缩到 64px 仍能分辨种类。

## T11 UI / 流程规范（2026-10-31）

- **星级**（UI_SPEC §3.4）：一次对局撤销与重开的合计次数为 0 得 3 星；合计 1–3 次得 2 星；合计 ≥4 次得 1 星。提示不影响星级。步骤显示当前解法的有效移动数（撤销移除该步），最优步数直接读取关卡中已被证明的 `solverMinMoves`，不再次阻塞求解。星级是可重玩的奖励，不限制通关/解锁，也不改变 Core 规则。
- 撤销与重开计数按关保存，退出/重新进入未通关关卡不清除计数；已通关后的 Replay 或选择已通关关卡开始新的评级对局。保留历史最高星数。首次迁移的 v3 已通关关卡因没有操作历史，授予基准 1 星，可重玩提升。
- **提示**：每关总计最多 3 次，重开、重玩、退出都不补充；重置进度才重置。后台线程在棋盘快照上执行 Solver，节点预算 6000，UI 等待预算 1.5 秒。仅当求解器证明最优时显示第一步的起点/终点；超预算/无解/搜索中的旧棋盘失效不扣次数。超时计算仍受节点预算约束，结束前不会启动第二个搜索，主线程每帧保持响应。没有广告。
- **教学**：1 关按“点来源 → 点同色/空栖木 → 连续同色一起飞”渐进；2/3/8/11/12/20 关分别教授鸟巢、睡眠、篮子、板条箱、短枝、两种揭示条件。首五关采用 UI_SPEC v1.1 柔边镂空遮罩，仅允许点击镂空目标和 Skip；手指使用素材并循环点击。第 1 关随真实选择与移动结束教学，第 2/3 关点击镂空区域继续。未确认的课程再次进入仍提示，v1.2 不再提供重看引导入口。减少动画时手指静止。
- **导航**：主菜单森林背景直接承载 Perch Sort 标题、树冠小鸟与浮动按钮，Play 继续保存的对局。关卡选择保持 4 列，使用裁切滚动内容，数量由 catalog 决定；显示星数、锁、当前关绿色脉动和总进度。v1.2 使用纯图标按钮，HUD 只显示关卡数字；通关保留三星/奖杯和图标操作，删标题横幅与步数行；最后一关仅有 Home/Replay。
