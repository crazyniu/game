# Wire drawn flight frames into every flight (OMP worker, issue 62)
Owned: `Scripts/Game/BirdView.cs`, `Scripts/Game/BoardView.cs`, new `Tests/PlayMode/FlightFramesTests.cs`. All art exists now: for every species `<species>_flight_takeoff_01..03`, `_flight_flap_01..06`, `_flight_land_01..03` (right-facing) and the same with `_l_` (left-facing) in `Resources/Birds/`.
Rules (exact):
1. Applies to every flight: transfer between branches, entrance flights from outside the screen, flights into the goal birdhouse, hatch/gift flights that use the same flight routine. Path shape, durations, easing and callbacks stay exactly as they are today (including the entry duration/easing parameters); only the drawn frame changes.
2. Frame selection by elapsed flight time T (seconds) and total duration D: takeoff frames for the first min(0.18 s, 0.2 D) split evenly over 3 frames; landing frames for the last min(0.22 s, 0.25 D) split evenly over 3 frames; the wing-beat loop frames in between, cycling at 14 fps continuously (frame index = floor(14 times elapsed time in the middle phase) mod 6, so the beat is continuous and not restarted per flight position). Flights shorter than 0.4 s use takeoff then land only.
3. Direction: target.x > start.x uses the right-facing frames, target.x < start.x the `_l_` frames, equal x uses the species' resting facing (right-facing). Never mirror any sprite.
4. Landing: after the last landing frame the existing 0.10 s landing squash plays, then the bird returns to its idle state; no pop to a different pose size (all frames share canvas, pivot and baseline).
5. A missing frame set (probe the first frame of each phase, cache per species) falls back to the current `fly_up`/`fly_down` behaviour without any added transform.
6. Honour `GameMotion.Instant` (no frames shown) and cancellation (a cancelled flight leaves no stale frame; reset to the idle frame).
Evidence: 0.05 s contact sheet of (a) a short left-to-right transfer, (b) a long right-to-left transfer, (c) a homeward flight into a house, (d) the level entrance, with the frame name under each tile; CSV of frame names; all under `docs/work-log/flight-frame-wiring/evidence/`. Tests: frame order takeoff then flap then land, 14 fps cadence within one frame, direction selection for both signs, fallback for a species whose frames are removed in the test, no negative scale.x, cancellation resets.
