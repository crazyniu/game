## Implement in Core (pure C#, no UnityEngine)

1. **Schema** (§12): level `world, variant, capacity, par, dayLength (0 = no day/night)`; branch `side, row, kind (normal|twig|growing|swivel), seats`; bird tokens `species`, `species:sleep`, `species:mama`, `species:chick`, `egg:species`, `crow`. Defaults keep level 1 valid.
2. **State**: per-bird stable id, species, flags (egg, asleep, mama, chick, revealed-egg), per-branch kind and current seats, homed species set, Song meter, chain, move count, day/night phase + counter, pending "light step" token, booster inventory snapshot for undo, Sapling used flag.
3. **Actions** (each an undoable history entry): `Transfer(from,to)`, `Swivel(branch)`, `UseBooster(kind[,target])` for Firefly (no state change other than consuming one; returns the hint), Sapling, OwlEye, MorningBell, Scarecrow, SpringRain.
4. **Rules** exactly per doc: runs (awake, non-egg, same species; crows run with crows), legal targets (seats, same-species tip incl. sleeping tip, crow tips, light step override), mama-pulls-chicks (§6.6), twig never completes, crow branch never completes, sleeping birds block completion until awake, flock size = level capacity N, growing branch +1 per homecoming (and mint gift), the fixed **resolution order** in §1 including homecoming gifts §6.5 for all 9 species, wake rules §6.2, day/night §6.8 (nocturnal = ink, hoot), Chorus/Song meter §7 (meter persists across levels: expose it as input/output of the session, do not store globally in Core), win, no-moves detection.
5. **Events**: emit an ordered event list per action for the view (Transferred incl. bird ids and per-bird from/to seat, ChicksFollowed, Hatched, EggRevealed, Woke, FlockHome(branch, species, ids), Gift(species, effect), BranchGrew, TwigUpgraded, CrowsLeft, Swivelled, PhaseChanged, SongNote, SongPayout, BoosterUsed, Won).
6. **Solver**: BFS/IDA* over the full state (including phase, light-step token, seats), without boosters; returns shortest path for Hint/par, plus `MinMovesByCompletionOrder` helper used by validation (§6.5 ordering rule). Must handle 7 species × 4 within a few seconds or report budget exhausted as Unknown (never claim unsolvable on budget exhaustion).
